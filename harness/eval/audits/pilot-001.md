# 判据审计试点 pilot-001

> **状态：已审计**（审计人 = 独立会话交叉审；实施者 = builder，不得自任审计人）。
> 机器可读记录：`harness/eval/audits/pilot-001.json`；三个率由
> `python3 -m harness.eval.cli audit --findings harness/eval/audits/pilot-001.json --audited-total 10 …` 复算。

## 抽样口径

- 抽样框 = **全部正式用例**（ADR-0005 指标表：新增用例 100% 审计，存量按季度抽样）。
- 本次试点 = 10 条：新增正式用例 **3** 条（`cap-001..003`）+ 抽样的存量用例 **7** 条
  （既有 CS 用例，外部引用；逐条在 finding 里点名实际审计的 `@test`）。
- `judge_defect_rate` 的分母 = **被审计的 oracle 数**（= 10）；`audit_coverage` 的分母 =
  **抽样框大小**（= 10，本次抽样框即这 10 条）⇒ 覆盖率 = 1.0。
- `false_negative_rate` 的分母 = 合法解尝试次数；本次为 **0 次** ⇒ 记 0.0
  （**不得**据此宣称「判据不过严」）。

## 审计结论

审计人判定：**REJECT（不予背书）** —— 10 条 oracle **全部有缺陷**。

- `judge_defect_rate: 1.0`
- `audit_coverage: 1.0`
- `false_negative_rate: 0.0`
- 缺陷分类分布：**过窄 1**（cap-001）、**可绕过 5**（cap-002、cap-003、cs-e1、cs-e2）、
  **依赖环境 5**（cs-e3、cs-e4、cs-e5、cs-e6、cs-rdd-1）；**过宽 0**。
- 主要缺陷类型：**可绕过**（判据与被测行为脱钩或恒真 ⇒ 假绿）与**依赖环境**
  （判定押在宿主插件 / CLI / Python 包 / 额度上 ⇒ 假红或静默空转）。

**冻结：冻结扩量**（阈值 0.10，唯一真源 = ADR-0005 §1 指标表；`1.0 > 0.10`）。
⇒ capability 集**停止新增**，先修判据。

**作废**（ADR-0005：「发现缺陷 ⇒ 该用例作废并重审，**不得沿用旧结论**」）：
`cap-001`、`cap-002`、`cap-003` 三条正式用例作废 ⇒ 转入 pilot-002 重审。
存量 7 条 CS 用例的缺陷属**既有测试套件**的问题（缺插件加载探针、外部引用读已安装副本、
`jsonschema` 缺失即跳过校验等），**不在本 change 范围**；已在 §「登记的欠账」中留痕。

## 逐条 finding

| oracle_id | 缺陷分类 | 要点 |
|---|---|---|
| `cap-001` | 过窄 | 只查单一路径存在性 ⇒ 其它路径被写仍判绿；`git_status_clean` 已实现却无用例使用 |
| `cap-002` | 可绕过 | 只判「什么都没改」，**无正向停机判据** ⇒ 只回一句话的解同样绿；fixture 写在 case 之外 |
| `cap-003` | 可绕过 | 退出码检查跑的是 case 自带硬编码命令（恒真、与被测行为无关）⇒ 失败被吞掉也判绿 |
| `cs-e1` | 可绕过 | `role.json current_role` 由 fixture 预置 ⇒ 检查恒真；用户问题是否被回答从未断言 |
| `cs-e2` | 可绕过 | 写目标只认 edit/write/multiedit/patch（shell 写盘是盲区）；`git status` 事后 `git checkout` 可恢复 |
| `cs-e3` | 依赖环境 | 依赖宿主加载插件 + 真实模型 + 额度 + 固定 fixture 根；两文件对同一宿主的假设互相矛盾 |
| `cs-e4` | 依赖环境 | 缺「commit-gate 插件已加载」前置探针 ⇒ 环境缺失与门禁失效同形（假红） |
| `cs-e5` | 依赖环境 | 缺「push-gate 插件已加载」前置探针；「是否发起 push」口径偏宽（dry-run 也算） |
| `cs-e6` | 依赖环境 | 判据读**已安装副本**（陈旧则假绿）+ 断言宿主 PATH 上的 openspec / bats 版本 |
| `cs-rdd-1` | 依赖环境 | `jsonschema` 缺失即 `exit 0` 跳过校验 ⇒ 契约锁静默空转（假绿）；它是 arch 阶段的证据集锚点 |

（逐条完整依据见 `pilot-001.json` 的 `findings[].reason`。）

## 冻结与解除

- 冻结判据：缺陷率 > 10% ⇒ **冻结扩量**（先修判据，不新增用例）。
- 冻结落点：本文件「审计结论」段的 `冻结` 字段 + `pilot-001.json` 的 `freeze_expansion`
  字段（两者必须一致，由 `harness/tests/test_audit_record.py` 核对）。
- 解除条件：缺陷用例作废并**重审**（ADR-0005：不得沿用旧结论）⇒ 重审生成 `pilot-002`，
  `pilot-001` 保留为历史记录（不作废、不删除）。
- **本轮的实际解除路径**：`cap-001..003` 按审计给的最小修复方向修好后重审（pilot-002）；
  存量 7 条 CS 用例的缺陷修复属既有测试套件的欠账（见下），不作为本 change 的解除条件。
