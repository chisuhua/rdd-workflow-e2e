## 背景与问题

ADR-0007 定了「哪个阶段由谁承担」这个问题的**归属形态**，但没定「怎么测」。缺口有六处：

1. **臂怎么定义**：两个载体不互斥（ADR-0007 决策 1）⇒ 臂不是「两套流程」二选一，而是**阶段编排等级**（W0 / W1 / W2，见决策 1）。不定清楚，对照就是范畴错误。
2. **臂怎么强制**：若用 prompt 请求「别用 skill」，臂间差异会混入「模型是否听话」⇒ 对照失效。
3. **标签放哪**：O 层指标从 session DB 算；臂标签若进 DB / trace，则（a）被测进程可写 ⇒ 可自报；（b）solver 可见 ⇒ 泄露。
4. **怎么算分**：单一「共同产物」定义会偏向一臂（ADR-0007 决策 2 与 `dual-path-model.md` §3）。
5. **统计与成本**：各臂都跑真模型 ⇒ 吃额度；且小样本 Δ 只能标方向性（ADR-0005 §4）。
6. **要不要基线臂**：**W0 是「编排层消融」**，直接先例 = Claude Code plugin eval 的 `WITH / W/OUT` **两臂**（`docs/research/01-harness-and-eval-engineering.md:24`）；`docs/research/01:35`（Agentless）**只作动机引用**（「scaffold 的贡献须可归因」）。⚠ W0 **不是**该条目意义上的「非 agent 基线」—— W0 仍是完整 agent loop（LLM + 工具 + 宿主），只是摘掉**阶段编排**；真·非 agent 基线（固定 pipeline，回答「模型 vs scaffold」的全归因）**不在本期范围**（治理基座常开 ⇒ 本设计测不到那一层）。⇒ 缺一个编排层消融臂，增量无法分解。

## 决策

### 1. 臂集合：阶段编排等级（三级，含基线参照臂）

> **字母约定**：臂等级用 **W**（workflow level）—— **W0 / W1 / W2**；⚠ 刻意避开 `L`（本仓 `L1/L2/L3` = **测试层**）与 `P`（`P0/P1/P2` = **分期**），也与 harness 的 `O/E/R` 三层不撞名。

| 臂 | 编排等级 | 定义 | 角色 |
|---|---|---|---|
| **W0** | **无阶段编排** | 不切角色、不产阶段工件、不走 rdd skill；system prompt 用**评测面自带的通用 prompt 副本**（不改治理面真源） | **参照臂**：回答「编排整体值多少」 |
| **W1** | 内置编排 | 角色矩阵照常；产出 planner / builder 阶段工件 | **主比较的一侧** |
| **W2** | 内置编排 + rdd skill 叠加层 | 当前真实分歧：哪个阶段由谁承担 | **主比较的另一侧** |

- **主比较 = W1 ↔ W2**（回答「阶段归属边界」）⇒ **归属决策只用这一对**（ADR-0007 决策 3 的门槛）。
- **参照 = W0 ↔ W1 / W0 ↔ W2**（回答「编排的增量」）⇒ **方向性，不进入任何归属决策**。
- **三臂产生增量分解，不产生排行榜**（见决策 8）。

**W0 的两条实现路径与取舍**

| 实现 | 做法 | 判别力 | 代价 |
|---|---|---|---|
| (a) 单角色 agent | system prompt 不换，只是不切角色 / 不产阶段工件 | **弱**：内置矩阵文本仍在上下文里，行为仍被其影响 ⇒ 测的是「用不用编排」，不是「有没有 harness」 | 低 |
| (b) **通用 prompt 副本**（**默认**） | 评测面自备无角色矩阵的 system prompt 副本，**不改治理面真源**；prompt 集合的哈希记入 manifest（沿用 `prompt_version` 口径） | **强**：对应 research/01 的「三个旋钮 = system prompt / tools / middleware」 | 中（多维护一份 prompt 副本） |

⇒ **副本的落点与漂移策略**（2026-11-27 定）：副本落 **`harness/eval/**`**（⇒ 自动进安全核，ADR-0004 决策 4）；副本是**稳定标尺**，**不随治理面 `build.md` 漂移**（漂移会使 W0 的历史结果不可比）；若确需跟随治理面演进 ⇒ **须人审并记录**（落 `.rddf/reviews/`）。

⇒ 默认取 (b)；(a) 仅在需要「只消融编排、不消融 prompt」时追加，**且必须单独标注，不得与 (b) 混算**。

**W0 的约束（三条硬边界）**

1. **治理基座不可关**：宿主强制层（角色写门 / commit 门 / push 门 / 委托契约）**在 W0 臂仍然生效** ⇒ W0 是「无编排」，**不是**「无约束 agent」；任何「关掉治理面以求干净对照」的方案**不接受**（违反 ADR-0007 决策 1 与安全核）。
2. **任务适配性**：多阶段任务上 W0 的失败可能是「任务本来就需要编排」而非「臂更差」⇒ case 元数据须声明 `task_orchestration_intrinsic`（bool）；**声明为「内在需要编排」的任务，其 W0 结果不计入 W1/W2 的相对比较**，单独进「任务适配性分布」报告。该声明须**附一句理由**，并进 **ADR-0003 决策 3 的审计记录**（`{case_id, oracle_sha, auditor, author, defects[], verdict, date}`）与决策 4 的 100% 审计要求 —— 无理由、未经审计的标记 = 审计无法证伪 ⇒ 可被当成「挑数据」的口子。
3. **流程层分两类（且各类再分子项）**：
   - **① 宿主强制类** —— 由**宿主层**（插件 / 权限系统）保证，**所有臂都适用且应当一致**（W0 也不例外 ⇒ 这是「治理基座不可关」的正面证据）：越权写被拒、commit / push 门拦截与放行。
   - **② prompt 驱动类** —— 由**prompt 文本协议**驱动，**W0 不适用**（W0 用无角色矩阵副本，结构性不产生这些子项）：非交互停机三件套（停机标记 / 候选路径 / 零写）。
   - **③ 阶段工件类** —— W0 **不产阶段工件** ⇒ 标「**不适用**」：工件归属合规、阶段 gate 纪律、改进记录。
   ⇒ 「不适用」项**不得**记为「不达标」（否则 W0 被结构性判负）。
   ⇒ 「应当一致」指**安全不变量的断言**（不一致 ⇒ **判红**并单列），**不是**性能比较（性能比较只在任务层做，见决策 3）。

**其余臂内规则（W1 / W2 通用）**

| 项 | 规定 |
|---|---|
| **强制执行（遮蔽为主）** | 非当前臂的叠加层必须**从环境中摘除**（遮蔽），**禁止**用 prompt 请求式 |
| **权限 deny 的适用范围** | 宿主 `skill` 权限是**工具级**、**无 per-skill 粒度** ⇒ deny 会连非 rdd skill（`cmake` / `tavily-search` 等）一起拒，且拒绝事件进 trace 污染工具错误协变量 ⇒ **权限 deny 仅用于「零 skill 需求」任务**；其余任务一律用环境遮蔽，并在报告声明该局限 |
| **可推断性（诚实边界）** | solver 能从「可用 skill 列表」反推自己的臂 ⇒ **盲化是部分的**；「臂标签不进 solver 视野」只保证**标签本身**不泄露，不保证**臂不可推断** |
| **盲化的机械层** | 报告生成默认匿名臂名；揭盲需显式 `--reveal` 并留痕（操作者 + 时间）。**人际层面的「审阅者不见臂」不可机械验证 ⇒ 不写进契约** |
| **排除规则** | trial 内出现叠加层**切换**（`path_switches` 非空）⇒ 该 trial **不进配对样本**（仿 ADR-0002 对 `model_switches` 的排除）。`path_switches` 由 **runner 写入臂索引的扩展字段**（schema 见决策 2 的五字段形态：`{session_id, run_id, arm, path_switches[], prompt_hash}`），不落 trace |

### 2. 臂索引与 join（唯一的连接机制）

- 臂索引 = `session_id ↔ run_id ↔ arm` 的**唯一映射**，落 `~/.local/share/rddf-harness/arms/<run>/arms.jsonl`（**运行数据，不进 git**，ADR-0001 决策 2）；由 **runner 独占写**（ADR-0001 决策 4 的 single writer 表新增一行）。
- 每行含 **`{session_id, run_id, arm, path_switches[], prompt_hash}`**：`prompt_hash` = 该 trial **实际使用**的 prompt 集合哈希 —— 多臂 run 下各臂 prompt 不同（W0 用评测面副本、W1/W2 用治理面矩阵）⇒ **单一 `prompt_version` 无法代表各臂**（ADR-0005 §3：`prompt_version` 为并集哈希）。
- **不进** `trace`、**不进** session DB、**不进** solver 可见环境（ADR-0002 字段表因此**不新增**臂字段 —— 这是刻意的：被测进程不得持有臂标签）。
- `run-manifest.json`（`kind=eval`）记 `arms_index_sha256` ⇒ 结论可复现（ADR-0005 §3）。
- **切片只适用于 runner 执行的新评测**，**不回溯**历史会话（历史 1,854 个 session 无臂标签）。

### 3. 双层测量（各臂同分母 / 各臂各自合规，永不合成）

| 层 | 判据 | 分母纪律 |
|---|---|---|
| **任务层**（跨臂可配对） | 最终工作区状态达成 + 测试通过 | **无产物计为失败**，不是缺数据 ⇒ 各臂分母一致（ADR-0005 的 unknown 计入分母纪律）。**对称整对剔除**（overlay 诱发失败、见决策 4）**不改变**本条：被剔除的 task 两臂同退，分母口径不变 |
| **流程层**（各臂各自） | 宿主强制类（越权拒绝 / commit·push 门）+ prompt 驱动类（停机三件套）+ 阶段工件类（工件归属 / 阶段 gate / 改进记录） | **不跨臂比较**（只做「各自达标」的合规检查）—— **例外**：宿主强制类子项是**安全不变量**，要求各臂一致，不一致 ⇒ **判红** |

⇒ 报告**必须**分列这两层；**禁止**合成单一分数（ADR-0007 决策 2）。

⇒ **可回答域的显式声明**：

| 比较 | 能回答 | **不能**回答 | 能否作决策依据 |
|---|---|---|---|
| **W1 ↔ W2**（主比较） | 阶段归属边界（no-harm + 结构理由） | 「流程纪律 ⇒ 更好结果」的**因果**问题 | ✅ 唯一可用于**归属决策**的一对（ADR-0007 决策 3） |
| **W0 ↔ W1 / W0 ↔ W2**（参照） | 编排带来的增量**方向** | 增量大小（分辨率不足）；W0 是否「更好」 | ❌ 只标方向性，**不进入任何归属决策** |

⇒ 迁移决策的依据是 **no-harm + 结构理由**（gate 覆盖 / single writer），**不是** outcome 优势。

### 4. 配对口径

| 项 | 规定 |
|---|---|
| 比较方式 | **逐任务配对**（同一任务的各臂成对），不比较各臂的聚合率 |
| 配对键 | `task_id`（**跨 run 稳定**）⇒ partial run 可与后续 run 补配 |
| W0 的处理 | `task_orchestration_intrinsic = true` 的任务，其 W0 结果**不计入** W1/W2 的相对比较（单独进「任务适配性分布」）；**W0 ↔ W1/W2 的比较单独成表**，不与 W1 ↔ W2 混算。⚠ **选择效应声明**：剔除 intrinsic 任务后参照集偏向 W0 擅长面 ⇒ **编排增量被低估**（保守方向）；报告须显式声明该偏差与被剔除任务数 |
| **overlay 诱发失败** | W1 臂 = 「治理矩阵照常 + 叠加层被遮蔽」，而矩阵本身含 rdd-aware 分支与「skill 不可用 → 走内置流程」的 fallback ⇒ W1 的失败里会混入**因尝试调用被遮蔽的 rdd-\* skill 而产生的失败**（unknown-skill 错误）。⚠ **不得单边剔除**：单边从 W1 分母剔除会**抬高** W1 的失败率、与本 ADR 的「各臂分母一致」及 ADR-0005 的分母口径互斥。⇒ 改为**对称整对剔除**：该 task 的 **W1 与 W2 同时**退出主比较（配对结构保留，分母对两臂保持对称）；**剔除计数与占比进报告**；**剔除占比超阈值 ⇒ 该 run 判不可用**（阈值由实施层写死，防「靠剔除规避不利 task」）。⚠ 被测方可主动触发 unknown-skill 让某 task 被剔除，但剔除只让该 task **不贡献任何分数**（既不抬高也不降低自己）⇒ **不构成刷分路径**；阈值是防线 |
| 翻转数 | 每任务记四类之一：`improved` / `regressed` / `same` / `same-score-different-behavior`，四类计数进报告 |
| 「同分但行为不同」的操作定义 | **比较域 = 该 case 声明的 artifacts 清单**（ADR-0006 §4.1）；`changed_files` 落在 artifacts 清单外（如 `.rddf/state/**`、`openspec/changes/**` 等**流程工件**）时**不计入**；仅当 artifacts 域内的 `changed_files` 集合不同 **或** 任务层 oracle 的**子项得分向量**不同时，才判「同分但行为不同」并**拒收**该样本（不进入 Δ 计算，不计为 improved/regressed） |
| Δ 的效力 | **只标方向性**；阈值以 **ADR-0005 §4 为唯一真源**（分辨率 > 5pp 期间 Δ 不作任何决策依据，ADR-0007 决策 3） |
| 配对设计的敏感性 | 配对（逐任务翻转）比两比例检验更敏感，但**不因此放宽** ADR-0005 §4 的口径；两者的分辨率锚点各自标注来源 |

### 5. 成本熔断与预算记账

| 项 | 规定 |
|---|---|
| 预算 | 每次对照 run 设**预算上限**（`--max-cost-usd` 式）；触顶即**停止**该 run |
| 记账 | **上限值与实际消耗写入 manifest**：`budget_usd` + `cost_usd_actual`（按 ADR-0005 §3 的「只增不改语义」规则新增字段）⇒ 触顶 run 可复现、可对账 |
| 顺序偏差 | 各臂**顺序执行**会系统性截断后序臂 ⇒ 预算**按臂设限**（每臂独立上限）或**臂序随机化**（并在 manifest 记录实际臂序） |
| partial 的组合 | 触顶 run 标 `partial: true`，**不产出任何 Δ 结论字段**；其已完成的 trial **可按 `task_id` 与后续 run 补配**（补配后的 Δ 仍标方向性，且报告须给出补配来源）。**`partial` 落报告（run 结果），不进 manifest 字段表**；manifest 侧对应事实是 `budget_usd` / `cost_usd_actual`（触顶时可据此推导） |
| **试点子集构成** | W0 试点使用的任务子集须**预先声明**（进 case 元数据或 run manifest），**不得事后挑选**；报告须**分列** W0 配对分母与主配对分母（分母不同 ⇒ Δ 不可直接相减） |

### 6. 干净环境与跨臂污染

ADR-0003 决策 3 的干净环境清单（`HOME` / opencode session 目录 / git 历史 / `TMPDIR` / 工作区）**追加两项**：

- `.rddf/state/**`（否则 run1 的 handoff / iteration 状态泄进 run2）；
- **叠加层的全部可达面**（不只 skill 目录）：

  | 遮蔽对象 | 形式 |
  |---|---|
  | `~/.agents/skills/rdd-*`（per-skill 软链） | 摘除 |
  | `~/.agents/skills/_lib`、`~/.agents/skills/rdd-workflow` | 摘除 |
  | `~/.local/bin/rddf`（wrapper） | 从 PATH 移除 |
  | `PYTHONPATH` / `RDD_WORKFLOW_REPO` 注入 | 不注入 / 清空 |

⇒ 只摘 skill 软链而保留 `rddf` CLI 在 PATH，叠加层机制**仍然可达** ⇒ 遮蔽必须覆盖上表全部四行。
⇒ 各臂**顺序执行**，run2 开始前对上述路径做**存在性断言**（文件系统事实，非 grep），**方向按臂条件化**：**禁用臂 ⇒ 断言四类对象均不存在；启用臂 ⇒ 断言四类对象均存在**（臂序随机化时同样按臂条件化 ⇒ 不得一律断言「已摘除」）。

### 7. 判据准入与规模计数

- 对照 case 进 capability 集须满足 **ADR-0003 决策 3 的 8 条**（含 reference solution **通过**该 oracle、替代正确解也通过、变红演练、干净环境、case 定义对 solver 不可达、审计记录）+ 本 ADR 的任务层 oracle + **100% 判据审计**（ADR-0003 决策 4，`auditor ≠ author`）。
- 「capability 正式集 ≥ 30 条」（ADR-0004 的 P2 恢复条件）**按任务计，不按臂计** ⇒ 配对子集的各臂**不双倍计数**（防门槛被稀释）。
- 配对子集使**判据审计预算翻倍**（ADR-0003 决策 4 的固定预算行）⇒ 试点规模须按审计工时反推，不得按「凑够 30 条」倒推。

### 8. 显式非目标与不削弱条款

- **不产出**排名 / 单一总分（用报告**模板结构断言**验收，不靠措辞 grep）；**三臂尤其容易诱发排名** ⇒ 结论字段取值域固定为 `{阶段归属修订, 判据修订, 列入观察, 无结论}`。
- **W0 不进入任何归属决策**（只作参照）；**归属决策只用 W1 ↔ W2**。
- **不改变** ADR-0003 的统计效力条款、ADR-0004 的 P2 恢复条件、ADR-0005 的 **分母口径**与 gate 语义；
- **不引入**容器硬依赖（ADR-0006 容器档是否因本 ADR 触发 ⇒ 见 ADR-0006 §5 的补判定）。

## 选项对比

| 选项 | 结论 | 理由 |
|---|---|---|
| A. 用 prompt 请求「别用 skill」实现禁用臂 | 否 | 臂间差异混入「模型是否听话」⇒ 对照失效 |
| B1. 工具权限 deny 强制禁用 | 仅限「零 skill 需求」任务 | `skill` 权限是工具级、无 per-skill 粒度 ⇒ 会连非 rdd skill 一起拒，且拒绝事件污染工具错误协变量 |
| B2. **环境遮蔽强制禁用** | **选中（默认）** | 差异只来自配置，不来自模型服从度；可用列表快照 + 路径探针机械判定 |
| C. 臂标签写进 session DB 或 trace | 否 | 被测进程可写 ⇒ 可自报；且泄露给 solver |
| D. 臂索引留 runner 侧 + manifest 记哈希 | **选中** | 标签不可自报、不可见；仍可复算 |
| E. 只比一个共同得分（不分层） | 否 | 测的是宿主噪声 + 掩盖流程纪律（ADR-0007 决策 2） |
| F. 各臂合并成一个总分做排名 | 否 | 违反 ADR-0007 决策 2；把治理约束变成可被指标换掉的东西 |
| G. 不设基线臂（只做 W1 ↔ W2） | 否（但**分阶段**采纳） | 缺基线 ⇒ 增量无法分解（直接先例 = plugin eval 的 `WITH / W/OUT`，`docs/research/01:24`；Agentless 条（`:35`）**只作动机引用**——它讲的是「非 agent 基线」，与 W0 不是一回事，见背景第 6 点）；但三臂成本更高 ⇒ **P1 主比较仍只做 W1↔W2**，W0 以参照试点进入 |
| H. 用「关掉治理基座」做基线臂 | **否** | 宿主强制层不可关（安全核 + ADR-0007 决策 1）；W0 只消融**阶段编排**，治理约束保持不变 |

## 后果 / 代价

**正面**

- 臂差异来自配置而非模型服从度 ⇒ 对照有效。
- 标签不可自报、不可见 ⇒ 结论可信度不被被测方污染。
- 双层测量 ⇒ 既能回答「谁做得成」，也能回答「各自守没守规矩」。
- 配对 + 翻转数 ⇒ 在小样本下比聚合率更有信息量。

**负面**

- 每次对照要跑**三臂**真模型 ⇒ 额度成本 ≈ **双臂**方案的 1.5 倍以上（靠熔断 + 按臂设限封顶；W0 臂可用较小任务集做参照试点）。
- 遮蔽面要覆盖四类对象（软链 / wrapper / 环境变量）⇒ 编排更重，且漏一处即失效（Verification 第 1 条用探针兜底）。
- 顺序执行 + 干净环境断言 ⇒ run 时间变长。
- 「同分但行为不同」拒收 ⇒ 会丢掉一部分样本（分母随之变化，必须在报告里显式给出拒收数）。

**风险**

- **臂不可完全盲化**（skill 列表可反推）⇒ 结论强度受限；须在报告显式声明该局限，不假装是完整盲化。
- 遮蔽不彻底（漏 `rddf` wrapper 或环境变量）⇒ 禁用臂可能仍在跑叠加层机制 ⇒ 靠 Verification 第 1 条的探针暴露。
- `path_switches` 排除会缩小样本 ⇒ 排除计数必须进报告，否则分母不可复算。
- 熔断触发后被误当作「无差异」⇒ 报告须把 `partial` 与「Δ 无结论」区分开。
- 补配（跨 run）可能引入不同批次的模型波动 ⇒ 补配后的 Δ 仍只标方向性，且须记录补配来源。
