## 背景与问题

实际有**两个载体**参与 planner / builder：

- **内置基座**：`~/.config/opencode/prompts/build.md` 的角色矩阵（权限边界、审查配对、越权处理、非交互停机兜底、HANDOFF 凭据）；
- **rdd skill 叠加层**：`rdd-workflow/skills/{rdd-planner,rdd-builder,rdd-quick}/**` 与 `rdd-workflow/**/_lib/**`（工件归属、状态机、gate、归档、改进记录）。

**范畴澄清（本次修订的前提）**：两者**不互斥**。skill 层的 P2 阶段「agent 自己实施计划」，该 agent **仍在读**内置基座的角色矩阵 ⇒ 权限与配对约束照旧生效。所以问题不是「选哪条流程」，而是「**哪个阶段由谁承担**」。

现有 ADR 体系（0001~0006）留下三处空洞：

1. **没有层属与归属表述** ⇒ 「某阶段该由谁承担」只存在于散文与习惯，不可判定、不可复核、不可回滚。
2. **改进面风险混同**：安全核（ADR-0004 决策 4）把两处载体都列为 hard-deny，但白名单（决策 3）只有「prompt 的表述、示例、反例」——「rdd skill 文档的表述算不算 prompt 表述」在现文有二义 ⇒ 人审时没有差异化清单。**（本次修订已在 ADR-0004 决策 3 澄清：skill 文档表述显式纳入可提案范围，且不新增任何其他可提案面。）**
3. **归属结论没有合法的证据门槛** ⇒ 没有「什么强度的证据允许移动一个阶段」的明文 ⇒ 实践中要么什么都不动，要么被 Δ 的噪声带着动。

## 决策

### 1. 层属：基座（常驻）+ 叠加层（可选）

| | 内置基座 | rdd skill 叠加层 |
|---|---|---|
| 层 | **治理面基座** | **产品面阶段合同** |
| 承担 | 权限边界、审查配对、越权三要素、非交互停机兜底、HANDOFF 凭据 | 工件归属、状态机、gate、归档、改进记录 |
| 归属仓 | opencode 仓 | rdd-workflow 仓 |

⇒ 基座**始终生效**；叠加层在其前置条件满足时承担阶段执行。**任一方都不因另一方存在而失效**。

> 臂等级记号（ADR-0008 决策 1）：**W0** = 无阶段编排（参照臂）｜**W1** = 内置编排（基座）｜**W2** = 内置编排 + 叠加层。

### 2. 对照的产出形态：归属边界 + 判据修订，不是排名

对照产出：①「哪些阶段由叠加层承担、哪些必须留在基座」的**归属声明修订**；② 对应**判据修订**。

**禁止**：把各臂压成单一分数、总分或排行榜（各臂的载体与判据不同源，压成一个数即等于用指标换掉治理约束）。

### 3. 证据强度 → 决策权限（归属结论的唯一门槛）

| 证据强度 | 允许的归属决策 | 明确**不允许** |
|---|---|---|
| 方向性 Δ（capability 集规模 × N 的分辨率 > 5pp 期间，见 ADR-0005 §4）+ contract 0 回归 | 「无伤害证据，保留现状」；「列入观察清单」 | 迁移阶段归属；关闭任一叠加层；削弱权限 / 配对约束 |
| 判据层证据：contract 0 回归 + skip 不超基线 + 判据审计完成（`auditor ≠ author`）+ 人审通过 + **回滚集已演练**（回滚三元组 `patch + criteria_version + taskset_version` **＋ `path_config_version`** —— 归属声明本身必须可回滚，见 ADR-0005 §3） | **可修订归属声明**（把某阶段的承担者从基座改到叠加层，或反向），前提：该阶段的**任务层 oracle 在 W1 与 W2 上均达标**（**不含 W0** —— W0 是参照臂，intrinsic 任务按 ADR-0008 决策 1 约束 2 不计入比较），且**流程层合规在 W1 与 W2 上不劣于现状**（不含 W0，理由同上） | 关闭 / 退役任一方；放宽已知失败基线；改动安全核清单 |
| 完整 A/B（分辨率 ≤ 5pp，需约 1600 次/臂）+ 上述全部 | 可提出「合并 / 退役」的**提案**（仍须人审 + 安全核扫描 + 回滚演练） | 无证据的退役 |

⇒ **迁空 tripwire**：**「阶段」= 阶段执行型职责**（产出 openspec 工件 / handoff 的阶段）；基座的权限 / 配对 / 停机类约束**不计为阶段**（否则基座阶段数天然为 0 ⇒ 门槛永久触发、形同虚设）。**叠加层**承担的阶段数降为 0 ⇒ 该次迁移视同**退役**提案，适用本表第三行的全部证据要求（否则「逐阶段迁空」可绕过第三行门槛）。
⇒ **参照臂（W0，无阶段编排）的结果不进入本表任何一档**（ADR-0008 决策 1）：它只提供「编排增量方向」这一背景量，**不构成阶段归属证据**。
⇒ **可回答域**：本表第二行的门槛依据是 **no-harm + 结构理由**（gate 覆盖 / single writer），**不是** outcome 优势 —— 对照**不能**回答「流程纪律 ⇒ 更好结果」的因果问题（ADR-0008 决策 3）。

⇒ **迁移门槛显著低于退役门槛**，这是可判的差别：迁移只换「谁写这个工件」，不改变治理约束；退役会改变可用能力面。

### 4. 阶段归属必须是显式、可版本化的声明

归属不得只活在 prompt 散文里。本仓（评测面）持有**期望归属声明** `harness/path-config.yaml`：

- 它是**判据**（声明「该阶段应当由谁承担、应当产出什么」）⇒ 进安全核（ADR-0004 决策 4）；
- 每行必须含**五**列：`{阶段, 当前承担者, 证据强度, 移动门槛, 证据集}`；**「证据强度」与「证据集」为空的行数 = 0**（脚本 lint）。**「证据集」= 支撑该阶段判据的 case id 列表**（阶段 ↔ case 映射）—— 没有它，决策 3 第二行「该阶段的任务层 oracle 在 W1 与 W2 上均达标」这个前提**不可判定**；
- 版本 = 内容哈希，字段名 `path_config_version`（沿用 `prompt_version` 的内容哈希模式，ADR-0005 §3），进 eval manifest；
- 治理面与产品面**各自落地自己的实现**；本仓只持有期望声明并据此**运行时校验**；
- **漂移可见**：声明为叠加层承担的阶段必须真的产出对应 handoff（文件系统事实）；声明为基座承担的阶段必须**没有**对应 handoff。⚠ **适用配置**：这两条**只在「部署与声明一致」的配置下执行**（生产全量配置：叠加层在场）；在按臂遮蔽的**对照 run** 中**不适用** —— W1 臂遮蔽了叠加层 ⇒ 前者恒红；W2 臂里被声明为基座承担但叠加层仍在场 ⇒ 后者恒红 ⇒ 不得据此判红。

### 5. 两处改进载体：风险分列 + 人审清单分列

| 载体 | 变更类型（**若经人审落地**） | 可否**自动**提案 | 风险等价物 | 人审必答（本类专属） |
|---|---|---|---|---|
| `~/.config/opencode/prompts/**` | 表述、示例、反例 | **可**（**表述类**；**落地强制人审**，ADR-0004 决策 2 / 3） | **等效权限 / 配对变更**（机读块任一非空改动 ⇒ 逐行人审） | ① 是否触及权限或配对语义？② 机读块是否变动？③ 是否新增越权面？ |
| `rdd-workflow/skills/**` + `rdd-workflow/**/_lib/**`（`rdd-verifier/**` 仍 hard-deny） | `owns` / `not_owns`、阶段契约描述、handoff / gate 的实现机械 | **否** —— **实现类**路径 ⇒ 既不可自动生成、也不可自动落地，只能经人审落地（ADR-0004 决策 2 / 4） | **等效工件归属变更**（single writer 声明） | ① 是否改变「谁写哪个文件」？② 是否与既有工件归属表冲突？③ 是否新增 gate 绕过面？ |

⇒ **边界单一真源（不在本文另立）**：**「生成面」= ADR-0004 决策 3 的白名单（穷举）**；**「落地面」= ADR-0004 决策 2**（安全核路径经人审 + 安全核扫描）；**实现类路径禁入**。本表**只是风险分类与人审清单**，**不构成新的提案面**。
⇒ 两类**不得合并为同一条提案**（一次提案只改一个变量，ADR-0004 决策 6）。

### 6. 归属仓不变

内置基座的改动落 opencode 仓、叠加层的改动落 rdd-workflow 仓；本仓只产出证据与判据（沿用 `docs/known-gaps-and-ownership.md:7` 的既有拍板「跨仓缺口只在本仓记录，不动 opencode 仓」）。

### 7. 显式非目标与不削弱条款

- **不改变** ADR-0004 的 P2 恢复条件、ADR-0003 的统计效力条款、ADR-0005 的 gate 语义、ADR-0006 的隔离档位；
- **不产出**流程排名 / 单一总分；
- **不做**生产侧归因（记录「这次会话走了哪套配置」需 opencode 仓埋点，属跨仓另议；本期归属声明只服务 eval 复现）；
- **不定义**内置侧的变更审批流程（opencode 仓今天没有该流程 ⇒ 登记为跨仓缺口，不在本仓代定）。

## 选项对比

| 选项 | 结论 | 理由 |
|---|---|---|
| A. 两个载体视为同层竞品，做 A/B 排名选优 | 否 | 基座与叠加层不在同一层；排名会诱导把「治理约束」当成可被指标换掉的东西 |
| B. 只观测一个载体，另一个不纳入 harness | 否 | 基座是权限与配对的唯一载体，不观测 = 治理变更永远没有证据 |
| C. 层属 + 显式归属声明 + 证据强度门槛 + 两载体风险分列 | **选中** | 让「谁负责哪一阶段」成为可引用、可回滚、可校验的声明；把归属结论绑到明文证据门槛上 |
| D. 合并成一条（强制全部走叠加层） | 否 | 丢掉治理基座；与「工件归属规则」的 single-writer 约束冲突 |
| E. 维持现状，只在架构文档提一句 | 否（保留 revisit） | 不可判定 ⇒ 改进提案仍无判据可依；条件：归属声明落地且运行时校验为绿后重估 |

## 后果 / 代价

**正面**

- 「谁负责哪一阶段」从散文变成声明 ⇒ 归属决策可复核、可回滚、漂移会红。
- 归属结论绑定明文证据门槛 ⇒ Δ 的噪声不能直接推动流程改动。
- 两类改进风险分开审 ⇒ 人审清单差异化。

**负面**

- 多一份要维护的声明（`harness/path-config.yaml` + 版本号）⇒ 漂移风险集中但仍需校验。
- 「不能压成单一分数」意味着**不能**用一个数回答「该不该合并」⇒ 有些问题只能靠推理 + 人审。
- 本仓对两处载体都没有写权 ⇒ 改进闭环跨三个仓，交付周期长。
- 内置侧今天没有变更审批流程 ⇒ 提案落 opencode 仓时**无既有通道可走**，需该仓侧先补（跨仓缺口）。

**风险**

- 声明与实际行为漂移 ⇒ 靠运行时校验暴露（决策 4 的两条运行时校验项）。
- 人审清单分列后成本上升 ⇒ 每类提案的分钟数上限沿用 ADR-0004 决策 7。
- 「层属」被误读为「基座次要」⇒ 治理约束被悄悄降级 ⇒ 决策 1 必须写明二者**同时生效**。

## Verification（可勾选验收判据）

- [ ] `harness/path-config.yaml` 存在，其内容哈希与 eval manifest 的 `path_config_version` 相等。
- [ ] 归属声明每行含 `{阶段, 当前承担者, 证据强度, 移动门槛, 证据集}` **五列**；「证据强度」或「证据集」为空的行数 = 0（脚本 lint，可机判）。
- [ ] 「证据集」列的 case id 均可解析到任务集内的实际 case（可机判）。
- [ ] **迁空 tripwire 可执行**：构造一份「**叠加层**承担的阶段数 = 0」的归属声明 ⇒ 校验判红并要求第三行证据（脚本模拟）；构造「基座承担 0 个阶段」的声明 ⇒ **不触发**（基座的权限/配对/停机类约束不计为阶段）。
- [ ] 运行时校验：声明为叠加层承担的阶段，实际运行后**必须**产出对应 handoff 文件（文件系统事实）；缺失 ⇒ 判红。**仅适用于「部署与声明一致」的配置**（对照 run 中按臂遮蔽 ⇒ 不适用，见决策 4）。
- [ ] 运行时校验：声明为基座承担的阶段，实际运行后**不得**产出对应 handoff 文件；出现 ⇒ 判红。**仅适用于「部署与声明一致」的配置**（对照 run 中不适用，见决策 4）。
- [ ] 两类改进提案各有一份专属人审清单，且两份清单的条目集合 diff 非空。
- [ ] **自动提案面 ⊆ 白名单类型**（穷举，逐条类型匹配）：白名单未显式列出的变更类型**不得**出现在自动生成的提案中（可机判）。
- [ ] **自动提案集 ∩ 实现类安全核路径 = ∅**（实现类 = `_lib/**` + `harness/{metrics,criteria,eval}/**` + skill 目录下的非 `SKILL.md` 文件）—— 可机判：路径 glob 匹配。**注意**：表述类路径（`prompts/**` 文本、`skills/**/SKILL.md` 的表述段落）虽在安全核内，**允许**自动生成提案，但**落地仍强制人审**（ADR-0004 决策 2）。
- [ ] 若 prompt 内机读块（`<!-- capability:` / `<!-- role-class-write-set:`）的非空改动**经人审落地**，提案元数据标为「等效权限变更」。
- [ ] 若 `SKILL.md` 的 `owns` / `not_owns` 或 `_lib` 实现机械的改动**经人审落地**，提案元数据标为「等效工件归属变更」。
